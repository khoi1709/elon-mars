## Worker source review

The inspected built worker installs by `cache.addAll` over its embedded manifest, then on activation deletes older caches with the worker's own prefix. Fetch handling is limited to GET requests on the same origin and within the registration scope. Navigation fallback is attempted only when the network fetch rejects, and is excluded for paths matching `api`, `auth`, `login`, `signin`, `oauth`, `callback`, `assets`, `fonts`, or `mission-data`, plus final path segments that look like filenames/extensions. Other in-scope navigation requests fall back to cached `index.html`; non-navigation requests are intercepted only when their exact absolute URL is in the precache set, using cache-first then network fallback. Other requests are not intercepted. This is a source observation, not a runtime API-exclusion test.
