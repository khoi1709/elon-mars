## Evidence

- **Live activity inputs are misbound:** `src/game/mission/MissionGame.tsx:208-213` supplies `surveyContext` only for the active Lake rover, but sets `camera.heading` equal to `roverPose.heading`; framing comes from a UI toggle. Thus ActivityPanel does use `state.rovers.lake` when Lake is active, but it does not receive actual camera orientation/framing.
- **No survey camera path:** `src/game/mission/world/MissionWorld.tsx:139-150` CameraDirector follows active rover/Leo at fixed offset `(x, ground+47, z+62)` and looks at target; it has no `surveyCamera`, heading, or framing input. Canvas FOV is fixed at `46` (`:664-673`). Activity toggle and explanatory text (`MissionGame.tsx:212`, `ActivityPanel.tsx:351-363`) do not change this camera. Consequently, recorded heading/framing may pass rules without representing the rendered camera.
- **Overlay requirement fails:** Lake activity uses `ModalFrame` (`MissionGame.tsx:211-213`); every open panel pauses the world (`:292`, rendered at `:300`). No compact, nonmodal Lake overlay is present. Other modal behavior remains unchanged.
- **Landmark connection absent:** shared `LAKE_SURVEY_TARGETS` are at `(202,170)`, `(211,171)`, `(206,182)` (`activities/rules.ts:134-137`), with validation ranges wide 34, close 12, location 8 and aim 20° (`:249-268`, `:448-457`). Lake world geometry exists (`MissionWorld.tsx:299-314`), but the world source does not import/use those targets or place corresponding target landmarks at their exact shared coordinates. Rule thresholds and target data are implemented; world-target binding is missing.
- **Genuine rover entry is domain-guarded:** world dispatches `ENTER_ROVER` only for a rover candidate within 8 (`MissionWorld.tsx:548-562`); reducer requires started, no current rover, unlocked base and actor inside region (`state.ts:222-228,463-469`). No teleport/fake progress found in this path.
- **Controls and continuity:** ordinary activity buttons have 48px minimum (`ActivityPanel.tsx:59-62`); touch D-pad is 44px at narrow viewport (`mission.css:9`), below 48px. Keyboard W maps to `z:+1` (`MissionWorld.tsx:616-618`), while touch Up maps to `z:-1` (`MissionGame.tsx:240-241`): inconsistent. Keyboard held keys clear on focus/blur (`MissionWorld.tsx:564-591`); touch releases/cancel/leave clear input (`MissionGame.tsx:240-241`), but no explicit close handler clears held touch input (`:254-255`). Activity progress is dispatched to mission state (`MissionGame.tsx:286-287`); camera framing local state survives close, but it is not a real camera state.
- **Other authorized visibility/startup items not found:** fixed camera values above do not match offset ~5/9, FOV ~54; base interaction measures from region center (`MissionWorld.tsx:481-488`), not center+[0,+8]; start CSS uses `min-height:100vh` and has no `100dvh`/`overflow:auto` in its screen rule (`mission.css:4-5`). Ground contrast was not visually tested.
